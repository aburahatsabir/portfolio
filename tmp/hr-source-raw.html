01 — Problem Statement / The operational case for building

Fragmented records.
Delayed payroll.
Zero traceability.

A 120-employee SME was managing HR operations through a patchwork of spreadsheets, WhatsApp groups, and personal Google Drive folders. Compliance audits were panic events. Payroll took three days. Documents disappeared when staff left.

PAIN — 01
Payroll preparation was a 3-day manual ordeal
Twelve disconnected spreadsheets, each with different formula logic, maintained by different people. Cross-validating attendance with payroll required reading WhatsApp conversation history. A single mid-month salary change required manual updates across multiple files with no confirmation it was complete.
3 days → 72 staff-hours lost monthly
PAIN — 02
Attendance lived in a WhatsApp group — unverifiable
Daily attendance submitted as text messages. No timestamp integrity, no verification mechanism, no way to detect missed punches or late arrivals systematically. Leave balances were approximated from memory. A dispute about attendance three weeks ago was structurally impossible to resolve.
Leave disputes unresolvable in ~40% of cases
PAIN — 03
HR documents stored in personal accounts
Employment contracts, offer letters, and NID copies lived in personal Google Drive folders — not company-owned. When two employees left within three months, their contract files left with them. No version tracking. The "latest" file was whatever had most recently been renamed "FINAL." A compliance audit would have been a catastrophe.
Doc recovery rate post-exit → ~60%
PAIN — 04
Approval decisions made on WhatsApp — no record
Leave approvals, salary revisions, document issuances — all communicated via chat message. No formal record, no timestamp integrity, no way to reconstruct the decision chain six months later. The system literally could not answer: who approved this, when, and under what conditions?
Approval audit trail recoverable → 0%
PAIN — 05
Cross-department reporting was structurally impossible
Getting total headcount, payroll cost, or leave utilization across departments meant manually aggregating files with inconsistent structures. This report was never produced. Leadership made staffing decisions with no data. Finance couldn't predict monthly payroll cost with any precision.
Consolidated HR report → never produced
PAIN — 06
Equipment custody invisible — no exit clearance
Laptops, SIM cards, and mobile phones issued to employees and then forgotten. No custody register, no return workflow, no exit clearance checklist. Devices discovered missing only at the next procurement cycle. No mechanism for enforcing document or asset return on departure.
Asset recovery rate on exit → below 70%

01
Single source of truth was the unanimous demand
Every role cited data fragmentation as their primary pain. The architecture principle — one canonical employee record that all modules derive from — came directly from this convergence. No module was designed until the entity relationships were locked.
02
Compliance controls were the actual business case
Leadership agreed to fund the system after calculating payroll ROI. But the compliance architecture — audit log, period locking, document versioning — was cited as the reason they would trust the system. Controls are not features; they are the foundation of credibility.
03
Mobile-first was a structural requirement, not a preference
40% of the workforce uses smartphones exclusively. A system requiring desktop access fails before deployment for nearly half its users. The progressive web architecture and mobile layout were specified before any screen was designed.
03 — Product Strategy / Why "lite" and why these modules

Focused scope.
Complete operations.
No enterprise overhead.

ERP-Lite is not a smaller version of SAP. It is a complete HR operations system for the specific problems SMEs actually face — built with controls-first thinking and no features that would require a dedicated IT team to operate.

Why "Lite" — Deliberate Exclusions
ERP-Lite v1 excludes recruitment/ATS, full accounting ledger, benefits marketplace, multi-country tax engine, and drag-and-drop workflow builder. These are excluded not because they are unimportant, but because including them would require enterprise infrastructure to operate and would dilute the credibility of the core operations system.
→ The scope boundary creates the value proposition. "Lite but complete" beats "everything but unreliable."
Why 8 Modules — Connected, Not Isolated
The 8 modules were selected because they form a complete operations loop: Employee Records feed Attendance and Leave; Attendance and Leave feed Payroll; Payroll and Documents feed Approval Workflows; Approvals and all state changes feed the Audit Log; the Audit Log feeds Analytics. Removing any module breaks the loop.
→ Module selection was determined by data dependencies, not by feature checklists.
Why Controls Were Designed First
The audit log, soft-delete policy, payroll period locking, and approval workflow architecture were specified before any UI was designed. This is not standard product development practice — it reflects a deliberate choice that a system handling people's money and employment records must be trustworthy before it is convenient.
→ Compliance infrastructure is not overhead. It is the reason stakeholders will trust the system with real data.
Why Role-Based Access at API Level
Access control enforced at UI level is cosmetic — a hidden button can be revealed with developer tools. ERP-Lite enforces access at the API query level: an Employee role session requesting the payroll endpoint receives a 403, not empty data. The salary figure never travels across the network to an unauthorized session.
→ The distinction between UI-level and API-level access control is the difference between appearance and security.

06 — Workflow Walkthroughs / Four core operational flows

Every workflow
has a
complete state machine.

State machines were designed before any UI. Every status transition is explicit, every actor is defined, every edge case has a handling rule. These are not happy-path flows — they include rejections, escalations, and conflicts.

Leave Request — Complete State Machine
DRAFT
Employee creates. Balance checked. Date overlap validated against locked periods.
↓ Employee submits — system validates balance and period availability
SUBMITTED
Enters workflow queue. Tier 1 (Team Lead) notified. 48-hour SLA countdown starts.
↓ Team Lead acts — OR 48h passes → auto-escalates
UNDER REVIEW
Tier 2 (HR Manager) review. Validates policy eligibility and team coverage.
↓ Approved → balance deducted, payroll notified | Rejected → reason mandatory
APPROVED
Balance updated. Calendar flagged. Payroll engine notified for period impact.
REJECTED
Reason recorded immutably. Balance unchanged. Employee notified. Resubmission allowed.
↓ Approved leave → applied in next payroll run
IN PAYROLL
Leave days reflected in payroll computation. Unpaid leave creates deduction entry.
Auto-Approve Rule
Casual ≤1 day + prior month attendance ≥95%
Bypasses Team Lead tier. Routes direct to HR stamp. Full audit entry still written — the shortcut is operational, not a compliance bypass.
Escalation Rule
48-hour inaction triggers automatic escalation
The original approver receives a missed-action notification. Request routes to the next tier. This eliminates the "lost in inbox" failure structurally — not by policy, by system design.
Conflict Detection
Submission blocked if preconditions fail
Three hard blocks: insufficient balance, overlap with locked payroll period, leave type ineligible for contract type. These are not warnings — submission is structurally impossible when any condition fails.
Payroll Integration
Approval writes directly to payroll engine
HR Manager never manually communicates leave status to payroll. The approved leave event triggers a payroll input flag automatically. The payroll run reads this flag during computation.
Payroll Run — Complete State Machine
INITIATED
HR starts run. System validates: attendance finalized, no open leave, prior period locked.
↓ Validation passes — computation begins per employee
COMPUTING
Gross = base + overtime + allowances. Deductions = tax + PF + unpaid leave + penalties. Net computed.
↓ Computation complete — variance check runs (>15% flags records)
PENDING APPROVAL
HR reviews totals. Flagged variances require Finance clearance before MD approval.
↓ HR clears flags → MD sign-off requested
APPROVED
MD approves. Payslips generated per employee with entity branding.
↓ MD approval → period permanently locked
LOCKED
Period locked at DB level. No edits possible. Post-lock corrections create Adjustment entries only.
Variance Alert — Mandatory
>15% net pay deviation vs prior month blocks progression
Finance review is not optional. Run cannot proceed to MD while flagged records are uncleared. Catches errors without blocking legitimate changes (new hires, revisions).
Period Lock — Permanent
Locked period cannot be modified — only adjustment entries
Post-lock corrections create a new Adjustment PayrollEntry referencing the original run. The error cannot be silently fixed. Both the error and the correction are permanently in the audit log.
Exception: Expired Document
Expired ID document blocks payslip release for that employee
Payroll run continues for all other employees. The specific employee's payslip is held in PENDING state until the document exception is resolved. This prevents one bad record from delaying the entire payroll cycle.
Document — Complete Lifecycle State Machine
DRAFT
HR creates from template or blank. Version 1. Employee linked. Type defined.
↓ HR submits for MD sign-off — version number locked
PENDING SIGN-OFF
MD reviews. Revisions increment version. Every version preserved — no overwrite.
↓ MD signs → document issued
ISSUED
Available in employee self-service. Physical copy tracked in custody register.
↓ Employee signs / acknowledges
SIGNED
Acknowledgement recorded with timestamp. Document legally executed.
↓ On expiry date → status automatically transitions
EXPIRED
Alert generated. Renewal workflow triggered. Prior signed version preserved in archive.
ARCHIVED
Still retrievable. Still attached to employee record. Never deleted. 5-year minimum retention.
Version Control
Every save is a new version — no overwrite
"FINAL_v3_ACTUAL.docx" is structurally impossible. The system never allows overwrite. Prior versions are always accessible with their author and timestamp.
Expiry Blocking
Expired ID document blocks payslip release
Document expiry is not cosmetic. An employee with an expired mandatory document has their payslip held in PENDING state until resolution. The block is enforced at payroll run time.
Exit Clearance
Employee cannot exit with documents in Issued status
Exit clearance checklist is system-generated. Every document in Issued status appears automatically. Completion of exit is blocked until all items are returned or marked as waived with a reason.
Attendance Exception — State Machine
OPEN
System auto-creates exception for missed punch, late beyond threshold, or invalid span.
↓ Employee submits correction reason (or Team Lead initiates)
SUBMITTED
Correction reason attached. Team Lead and HR notified for review.
↓ Team Lead reviews correction reason
REVIEWED
Team Lead recommends approval or rejection with comments.
↓ HR finalizes — attendance status updates, payroll impact recalculates
RESOLVED
Corrected attendance record created. Original exception preserved. Payroll impact updated if period open.
REJECTED
Original anomalous record stands. Absent/unpaid treatment applied. Audit entry written.
Auto-Exception Creation
System creates exceptions automatically — no manual reporting
Missed clock-out, late arrival beyond threshold, and negative/invalid time spans create AttendanceException records automatically at end of shift. No HR manual intervention required to catch anomalies.
Payroll Impact Rule
Unresolved exception = absent treatment in payroll
If an exception is still OPEN when the payroll period closes, the system treats that day as absent. The correction process must happen before the payroll period locks. This creates urgency without requiring manual tracking.

08 — Controls & Compliance Design / Architecture enforces behavior

Compliance is
architecture,
not a checkbox.

Every compliance requirement — record retention, approval audit trails, document versioning, payroll lock integrity — is enforced at the schema and API level. Policies cannot be accidentally bypassed because the system does not provide the mechanism to do so.

📋
Record Keeping
Service records retained 5+ years post-exit — soft-delete only, no physical removal ever at any role level
NID, DOB, blood group stored as verified fields — edits require HR Manager role and auto-write immutable audit entry
Every salary revision records: effective date, prior amount, new amount, approved-by, and reason — full trail for any inspection
Employment type tracked explicitly: Permanent / Probation / MTO / Contractual — each triggers different entitlement calculation rules
⚖️
Payroll & Leave Compliance
Annual leave entitlement encoded per employment type and location — factory vs commercial rates applied at computation time
Payroll period locking: locked months cannot be edited by anyone — corrections create adjustment entries with full approval chain
Post-lock adjustments reference original run ID, reason, and actor — the error and correction both permanently in audit log
Leave balance deducted only on approval, not on submission — pending requests do not prematurely reduce available balance
🔒
Data Protection
NID, personal mobile, bank details masked in list views — full values only visible to HR Manager and above at API query level
Photo and personal email optional with explicit consent flag — system enforces consent is set before data can be stored
Data export requires HR Manager minimum — export events logged with actor, timestamp, data scope, and format
Session tokens carry role claims — role checked at API query level, not at UI rendering level
🕵️
Audit Trail Architecture
Every write operation writes to audit_log before main transaction commits — if audit write fails, main write rolls back atomically
Full before/after state stored as JSONB — not just "field X changed" but complete record snapshot at that moment in time
Append-only at database level — no UPDATE or DELETE permission on audit_log table, including for Super Admin role
Audit entries exportable as structured CSV for labor authority submission — filterable by date, actor, entity, and event type

Payroll computation requires transactional integrity. A salary calculation that reads attendance and writes a payslip must succeed or fail atomically — partial writes create corrupted payroll data. PostgreSQL's ACID guarantees and row-level locking own this problem at the database level. A document database would require application-level transaction management for something the database should handle. The relational model also enforces foreign key constraints that prevent the referential chaos of the prior spreadsheet system.
100% of the workforce uses WhatsApp as primary communication. Email notification failure rate for factory and field staff was projected at 60%+ — most either don't have work email or don't check it. The system meets users where they are. A notification system that people ignore is not a notification system — it is a paper trail that nobody reads. The compliance value of notification only exists if the notification is actually received.
Senior leadership may hold roles across multiple legal entities with different salary structures, different tax liabilities, and different compliance obligations. Encoding this as one record with entity flags would require conditional branches in every payroll computation, every document template, every compliance check. Separate records with a person-level linking ID keeps every calculation clean — the complexity lives in the data model where it belongs, not scattered across application logic.
Policy can be overridden by someone with sufficient access and motivation. A database-level constraint cannot. If a salary was incorrectly calculated and later corrected, you need the original error, the correction, the actor, and the timestamps to all be permanently visible. A mutable log can be silently edited to remove the error — making it useless as evidence. Append-only at the database level is the only architecture that produces defensible evidence under scrutiny in a labor dispute.
UI-level access control is cosmetic. A hidden element can be revealed with browser developer tools in under 30 seconds. When an Employee session requests the payroll endpoint, the API checks the JWT role claim and returns a 403. The salary figure never travels across the network to an unauthorized session. This is the difference between "we hide the salary tab" and "salary data cannot be accessed by this session." For data of this sensitivity, only the latter is acceptable.

11 — Reflections / What building this proved

Three things
this project
proved.

Learned
Compliance infrastructure is the product — not a feature
The audit log, soft-delete policy, and period locking were initially scoped as Phase 2 compliance items. Discovery sessions revealed they were the core value proposition — the system was funded specifically because of these controls. In any system handling people's money or employment records, compliance architecture should be designed first, not retrofitted. It is not overhead. It is the foundation that makes every other feature trustworthy.
Challenged
Multi-entity isolation is harder — and more important — than it looks
The shared-employee problem required the most architectural rethinking. The tempting solution was an entity flag on one record. The correct solution — separate records per entity with a person-level linking ID — adds complexity at the data model layer but keeps every downstream calculation completely clean. Architectural decisions that feel expensive at design time pay for themselves every time a new feature is built on top of clean data.
Next Version
Biometric integration and mobile-native are the clear v2 priorities
The current attendance module trusts manager-verified records. For factory and field operations, biometric device integration — writing directly to attendance_records via API — removes human verification entirely and makes the data fully trustworthy as a payroll input. A mobile-native app for field staff would improve the experience for the 40% of users currently on browser. These are the two changes that would have the highest operational impact in v2.
